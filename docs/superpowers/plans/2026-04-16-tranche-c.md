# Tranche C — 新建 Tour 首次体验 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 走通"0→1"路径：新 Tour 自动有 D1 骨架、AI 首次进入自动多轮 onboarding 填 backlog、Backlog 空态提供三按钮引导。

**Architecture:** 后端 `Tour#after_create_commit :seed_first_day` 幂等 seed D1；`ChatStreamJob#system_prompt` 追加 onboarding 段 + 当前状态注入；`ToursController#show` 加 `conversation_empty` prop；前端 Show.jsx mount 时根据条件自动发送 sentinel 启动 onboarding；`ChatPanel.MessageBubble` 跳过 sentinel 不渲染；`BacklogList` 分三种渲染模式（empty editable / empty readOnly / normal）。

**Tech Stack:** Rails 8 · Inertia · React · Mantine · RubyLLM (OpenAI-compatible) · ActionCable · Vitest · RSpec

**参考 spec:** `docs/superpowers/specs/2026-04-16-tranche-c-design.md`

在 `app/jobs/chat_stream_job.rb` 顶部，`KIMI_LOOP_PATTERN` 常量后面加 sentinel 常量：

替换 `system_prompt(tour)` 方法为：

```ruby
    def system_prompt(tour)
      <<~PROMPT
        你是一个旅行规划助手。当前 Tour：#{tour.title}。
        所有 Day / Activity 工具已经自动绑定到这个 Tour —— 你不需要（也无法）
        指定目标 Tour，操作必然发生在当前 Tour 上。
        你通过调用工具修改 Day / Activity，不要直接输出 JSON 或 Markdown。

        ## 宪法约束（本程独立）
        #{tour.constitution.map { |k, v| "- #{k}: #{v}" }.join("\n")}

        ## 当前 Tour 状态
        - Days: #{tour.days.count}
        - Activities: #{tour.activities.count}

        ## 工具
        #{AITools::Schema.to_prompt_description}

        ## 交互原则
        - 先调用工具修改状态，再用自然语言简要解释
        - 需要时调用 run_constitution_check 验证，违反硬约束要主动提议修正
        - 需要 POI 或坐标时调用 search_poi，不要编造经纬度；从返回的候选里选一条 add_activity

        ## Onboarding 模式

        如果用户消息是 "#{ONBOARDING_SENTINEL}"，按以下节奏开始 4 轮对话：

        ① "欢迎 👋 我先问几个问题，搞清楚方向再开始。\n这次想去哪？（例如：伊犁环线、川西、河西走廊）"
        ② 用户答完 ① 后："几天？我会据此建 Day 骨架。"
        ③ 用户答完 ② 后："几个人、什么车？"
        ④ 用户答完 ③ 后："主要想看什么？（景观 / 人文 / 带娃 / 徒步…）"

        一次只问一件事，不要一口气问 4 个。

        收到第 ④ 个回答后，开始批量执行：
        - 当前 Tour 已有 #{tour.days.count} 个 Day（day_index 从 1 起步）。如果用户说 N 天，调用 create_day 创建 day_index = (#{tour.days.count} + 1)..N，跳过已存在的天。
        - 调 search_poi 搜索用户提到的地点，从候选里挑 add_activity 到 backlog（不指定 day_id，让用户自己拖）。
        - 添加 ~20-30 个 POI 即可，太多用户处理不过来。
        - 添加完毕回一句简短总结："已往 backlog 加了 N 个候选 + N 个 Day 骨架，往左拖到对应 Day 即可。"

        如果用户首条消息**不是** sentinel（例如直接说 "我想去伊犁"），跳过欢迎语，直接确认+进入第 ② 个问题。
      PROMPT
    end
```

关键点：
- 常量 `ONBOARDING_SENTINEL = "__onboarding_start__"` 在 `system_prompt` 里以 `#{ONBOARDING_SENTINEL}` 插值，保证前后端定义同源
- `tour.days.count` 在方法调用时即时读取（每次 LLM 轮回 job 重跑都会重读，准确反映当前状态）
- 不引入 schema 改动

import { useState, useMemo } from 'react'
import { Paper, Title, Stack, Text, Button, Group, Select } from '@mantine/core'
import { useDroppable } from '@dnd-kit/core'
import ActivityCard from './ActivityCard'

const KIND_FILTER_OPTIONS = [
  { value: '',       label: '所有类型' },
  { value: 'scenic', label: '景' },
  { value: 'road',   label: '路' },
  { value: 'food',   label: '食' },
  { value: 'stay',   label: '住' },
  { value: 'fuel',   label: '油' },
  { value: 'other',  label: '其他' },
]

const LEVEL_FILTER_OPTIONS = [
  { value: '',               label: '所有等级' },
  { value: 'tier_one',       label: '一等' },
  { value: 'tier_two',       label: '二等' },
  { value: 'tier_three',     label: '三等' },
  { value: 'infrastructure', label: '基础' },
]

export default function BacklogList({ activities, onAddActivity, onEditActivity, onAskAI, onFocusChat, readOnly }) {
  const [kindFilter, setKindFilter] = useState('')
  const [levelFilter, setLevelFilter] = useState('')

  const filtered = useMemo(() => {
    return activities.filter(a => {
      if (kindFilter && a.kind !== kindFilter) return false
      if (levelFilter && a.citizen_level !== levelFilter) return false
      return true
    })
  }, [activities, kindFilter, levelFilter])

  // Droppable uses full activities.length so dropped items are appended to
  // the true end (not after the filtered subset).
  const { setNodeRef, isOver } = useDroppable({
    id: 'backlog',
    data: { dayId: null, position: activities.length + 1 }
  })

  const isEmpty = activities.length === 0
  const hasFilter = kindFilter || levelFilter

  // Mode: empty + editable → dashed three-button frame.
  // Mode: empty + readOnly → simple "尚无候选" text.
  // Mode: normal (activities.length > 0) → current behavior (top + 加一个 + filters + list).

  return (
    <Paper withBorder p="sm" ref={setNodeRef} style={{ background: isOver ? '#f0f7ff' : undefined }}>
      <Title order={5} mb="xs">
        Backlog（候选池）
        {hasFilter && !isEmpty && (
          <Text component="span" size="xs" c="dimmed" ml={6}>
            {filtered.length}/{activities.length}
          </Text>
        )}
      </Title>

      {isEmpty && readOnly && (
        <Text size="xs" c="dimmed">尚无候选</Text>
      )}

      {isEmpty && !readOnly && (
        <Stack
          gap="xs"
          p="md"
          align="stretch"
          style={{ border: '2px dashed #ccc', borderRadius: 4, background: '#fafafa' }}
        >
          <Text size="xs" c="dimmed" ta="center">
            先把想去的点塞进这里，再拖到右侧 Day。
          </Text>
          {onAddActivity && (
            <Button size="sm" fullWidth onClick={() => onAddActivity(null)}>
              + 手动添加 activity
            </Button>
          )}
          {onAskAI && (
            <Button size="sm" variant="default" fullWidth onClick={onAskAI}>
              💬 让 AI 帮列候选
            </Button>
          )}
          {onFocusChat && (
            <Button size="xs" variant="subtle" onClick={onFocusChat}>
              ▸ 跳到 Chat 输入框
            </Button>
          )}
        </Stack>
      )}

      {!isEmpty && (
        <>
          <Group gap={4} mb="xs">
            <Select
              data={KIND_FILTER_OPTIONS}
              value={kindFilter}
              onChange={v => setKindFilter(v || '')}
              size="xs"
              w={100}
              allowDeselect={false}
              aria-label="按类型筛选"
            />
            <Select
              data={LEVEL_FILTER_OPTIONS}
              value={levelFilter}
              onChange={v => setLevelFilter(v || '')}
              size="xs"
              w={100}
              allowDeselect={false}
              aria-label="按等级筛选"
            />
          </Group>

          {!readOnly && onAddActivity && (
            <Button size="compact-xs" variant="light" fullWidth mb="xs" onClick={() => onAddActivity(null)}>
              + 加一个
            </Button>
          )}

          <Stack gap={4}>
            {filtered.map(a => (
              <ActivityCard key={a.id} activity={a} onClick={onEditActivity} readOnly={readOnly} />
            ))}
            {filtered.length === 0 && (
              <Text size="xs" c="dimmed">无匹配的候选。调整筛选或清空条件。</Text>
            )}
          </Stack>
        </>
      )}
    </Paper>
  )
}

## 附：实施注意事项

- **Sentinel 同步**：`app/javascript/lib/onboarding.js` 和 `app/jobs/chat_stream_job.rb` 的 `ONBOARDING_SENTINEL` 必须字面一致（都是 `__onboarding_start__`）。若将来要改，两处同时改 + 已存 DB 里的历史消息会变成可见的乱字符（接受）。

- **Day factory sequence 踩坑**：Day factory 有 `sequence(:day_index) { |n| n }`，全局递增。Task 2 的修复策略里若不显式传 `day_index: 2`，factory 可能在某个测试里恰好 sequence 到 1 并撞 seeded D1。已经在 Task 2 Step 5/7/8 等步骤里显式传 `day_index: 2`。如果 Task 2 执行过程中遇到某测试没想到的位置（也是 factory-seq-derived）失败，用相同模式修正。

- **ChatStreamJob 状态快照**：`system_prompt` 里的 `tour.days.count` 在 job 每次执行时重读，AI 多轮对话中每轮都会拿到最新值。如果 AI 一轮里连续批量调 `create_day`（同一次 `chat.ask` 里的多 tool call），state 可能已变化但 prompt 已经注入在 chat 开始——AI 会自行跟踪已创建多少（LLM 上下文跟踪能力足够应对）。

- **"conversation_empty" naming**：Rails / JSON snake_case，React prop 直接取同名即可（`function Show({ conversation_empty })` works）。不转 camelCase。

- **onFocusChat 暂不做 textarea focus**：spec §3.3 明确——只 `setChatOpen(true)`。若将来要精细聚焦 textarea，走 `pendingFocus` prop 扩展。

- **Tranche A/B 代码基线**：此 plan 基于 Tranche A + B + Fix 已落地的 `feature/tour-day-activity-remodel` 分支。合并前确认 `git log --oneline` 最新 commit 是 Tranche B / C 相关工作。

- **Inertia deep link + onboarding trigger 不冲突**：Show.jsx 已有一个 `useEffect([])` 处理 `#activity-{id}` hash。本 plan 追加的 onboarding trigger 是**另一个** `useEffect([])`——两者独立。若 URL 同时有 hash 和满足 onboarding 条件（e.g. 从 Timeline 跳回来且 backlog 刚好被清空），两个 effect 都会触发，打开 ActivityDrawer + 启动 onboarding。实际场景极少，接受。

- **"小 polish" + soft violation banner**：见 spec §4 "不做的"——dev 验收发现的 "整程 0 个机动日" banner 不在本 plan 范围。要处理的话单开 Tranche D 并先做产品决策。
